# 🥗 AI Nutrition Analyzer

Upload a photo of a dish and get an instant AI prediction of what it is, along with its estimated nutrition — calories, protein, carbs, and fat.

Under the hood it's a fine-tuned ResNet18 classifier (40 food classes, trained on Food-101) paired with a second general-purpose model that acts as a sanity check, catching non-food images the specialized classifier alone has no way to recognize as out of scope. Nutrition values are sourced from USDA's FoodData Central API rather than hardcoded.

## ✨ Features

- Upload a food photo through the browser and get a prediction with a confidence score
- Recognizes **40 popular dishes** (expandable list shown right on the page)
- Nutrition data (Calories / Protein / Carbs / Fat) pulled from **USDA FoodData Central**, not hand-typed
- Two-stage rejection so it doesn't confidently guess on things that aren't food:
  - a confidence + margin threshold on the specialized model's own prediction
  - a broader ImageNet-based sanity check that catches screenshots, unrelated photos, etc. that would otherwise fool the narrow 40-class model
- Shows the uploaded photo back alongside the result
- Clean glassmorphism UI, no clutter

## 🧠 How it works

```
Upload
  │
  ▼
General ResNet18 (1000 ImageNet classes)
  │   "does this look food-like at all?"
  ▼
Fine-tuned ResNet18 (40 food classes)
  │   "which of my 40 known dishes is this, and how confident am I?"
  ▼
Both checks pass?  ──No──▶  "Not a recognized food"
  │ Yes
  ▼
Nutrition lookup (CSV, sourced from USDA)
  │
  ▼
Rendered result: dish name, confidence, nutrition breakdown
```

The specialized model was trained by transfer learning from a pretrained ResNet18: the early layers (generic edges/textures/shapes) stay frozen, while the last residual block (`layer4`) and the final classification layer are fine-tuned on Food-101 images for the 40 selected classes.

## 🚀 Setup & Run

### Clone the repository

```bash
git clone https://github.com/RituPrabhat/NutriAnalyzer.git
cd NutriAnalyzer
```

### Create a virtual environment

```bash
python -m venv venv
```

**Windows**
```bash
venv\Scripts\activate
```

### Install dependencies

```bash
pip install -r requirements.txt
```

### Set up your USDA API key

Get a free key from [api.data.gov](https://api.data.gov/signup/), then create a `.env` file in the project root:

```
USDA_API_KEY=your_key_here
```

### ⚠️ Model weights and dataset are not included

`food_classifier.pth` and `data/raw/food101/` are gitignored (too large for version control). To run the app, you need to train the model yourself first:

1. Download the [Food-101 dataset](https://www.kaggle.com/datasets/dansbecker/food-101) and extract it into `data/raw/food101/`.
2. Generate the nutrition CSV:
   ```bash
   python scripts/download_nutrition.py
   ```
3. Train the classifier (this fine-tunes `layer4` + the final layer over 10 epochs — expect it to take a while on CPU):
   ```bash
   python -m src.image_classifier.train
   ```
   This saves `food_classifier.pth` in the project root.

### Run the app

```bash
python webapp/app.py
```

Open **http://127.0.0.1:5000** in your browser.

## 🧪 Model Details

- **Architecture**: ResNet18, pretrained on ImageNet, with `layer4` and the final classification layer fine-tuned on Food-101 images for 40 selected classes.
- **Training**: 10 epochs, Adam optimizer, 80/20 train/validation split.
- **Result**: ~75% validation accuracy across the 40 classes.
- **Rejection logic** (`predictor.py`): a prediction is only accepted as food if it clears a confidence threshold *and* a margin over the second-best guess *and* the general sanity-check model agrees the image looks food-like overall.

---

## 🥗 Nutrition Data

`scripts/download_nutrition.py` queries USDA's FoodData Central API for each of the 40 foods — preferring the `Survey (FNDDS)` dataset (built from real prepared dishes "as eaten") and falling back to `Foundation`/`SR Legacy` (raw ingredients) when a dish isn't covered there. It retries on transient API failures and flags any result whose macros don't mathematically match its stated calories, so bad matches surface instead of silently slipping into the dataset.

---

## ⚠️ Known Limitations

- **Closed-set classifier**: the model only knows its 40 trained dishes. A photo of a food outside that list (a raw fruit, a different cuisine) will still get matched to whichever of the 40 looks closest — this is inherent to any fixed-class classifier, not a bug to fully eliminate.
- **Not a medical or dietary tool**: nutrition values are per-100g estimates from USDA reference data, not measurements of your specific plate.
- **CPU training is slow**: no GPU-specific optimization is included; training 40 classes on CPU can take a significant amount of time.
